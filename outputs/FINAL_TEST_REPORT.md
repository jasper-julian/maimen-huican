新增 `test/export.test.mjs`（6 项）：

1. 没有填写想吃的人 → `wantCount = 0`，不虚报满足数；
2. 单项偏好满足 → `1 / 1`；
3. 多项偏好部分满足（预算 15 元，薯条加不进来）→ `1 / 1 / 2`；
4. 否决重排后计数随重新推荐更新（该人 `metCount` 由 1 变 0，`wantCount` 仍为 1）；
5. 4 人 × 4 策略全量：`0 ≤ met ≤ want`、`met + missed = want`、导出不含偏好原文与内部编码；
6. `exportCard()` 直调：分配对象上已无 `wants` 数组，计数仍正确。

另有 1 项加价受益人回归：只多分到同类餐品、没有新增关键词满足时，也如实列出“多拿到什么”。

所有错误、无解、超时、缺配置类用例均为**注入模拟**，不代表真实链路；真实链路见第 3 节。

## 3. 真实只读验证（`npm run test:live`）

上海 · 静安寺，2 人（A 想吃鸡肉、不吃辣；B 想吃牛肉、不吃鱼），到店自取场景。

- 门店：5 家，选「麦当劳上海静安寺餐厅」
- 菜单：88 个可用单品；门店优惠 3 个
- 工具调用：27 次（`query-nearby-stores` 1、`query-meals` 1、`query-store-coupons` 1、`query-meal-detail` 10、`calculate-price` 14），全部在白名单内
- 预算 ¥120，四种策略**全部**官方试算成功、商品编码与数量核对通过：

| 策略 | 官方实付 |
| --- | --- |
| 优先满足口味 | ¥86.00 |
| 优先节省预算 | ¥33.90 |
| 折中推荐 | ¥60.00 |
| 照顾最难满足的人 | ¥86.00 |

- 否决：B 对「高达吉士双牛堡」点“这份我不接受”→ 重排后四套仍全部试算成功（¥86.50 / ¥33.90 / ¥60.50 / ¥86.50），B 不再分到该项
- 加价对比（¥120→¥130）：无新组合，如实返回“方案没有变化”，官方实付仍 ¥60.50
- 加价对比（¥55→¥65）：口味方案 ¥46.50 → ¥60.50，新增麦乐鸡 ×1，`delta = 14.00`，受益人是“匿名 A 多拿到 麦乐鸡 ×1”
- 导出：`metCount / missedCount / wantCount` 与页面逐人一致（A 1/0/1，B 1/0/1），官方金额 ¥86.50，时间一致
- 优惠：本轮没有命中方案餐品的可用券，页面写“单券试算 0 项”，未宣称降价

证据文件：`outputs/live-verification.json`、`outputs/真实验证-脱敏方案卡.json`。
