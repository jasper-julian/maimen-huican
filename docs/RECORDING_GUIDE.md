# 麦门会餐：录屏操作与讲解脚本

本文件是录制计划，不表示视频已经录好。当前代码已加入四种策略、个人否决和相邻预算对比，录制时仍须以实际界面与当次官方返回为准。

## 录制前

1. 在本项目运行 `npm start`，打开 <http://127.0.0.1:4192/>。不要重复启动已经占用同端口的本项目服务。
2. 确认本机已有有效配置，录制期间不打开 Token 内容或个人收货地址。
3. 用 macOS `Shift + Command + 5` 录制网页区域。建议 2—4 分钟，网页中的真实等待可以保留或注明加速。
4. 使用公开商圈“上海 / 静安寺”；真实菜单、营业状态和价格以录制当时返回为准，不预设金额。

## 主演示顺序

| 阶段 | 实际操作 | 讲解重点 |
|---|---|---|
| 开场 | 展示首页、真实/演示状态 | “几个人想吃的不一样，先把预算和不能接受的食物说清楚。” |
| 连接 | 点击“重新检查连接”，等待官方连接状态 | 只查询与价格试算，不创建订单或付款；有效配置无需重复输入 |
| 门店 | 填城市“上海”、商圈“静安寺”，点击“只查询门店”，选择一家营业门店 | 使用公开商圈，不读取私人地址；清楚展示本次选择的门店 |
| 需求卡 | 人数改为 2、预算先填 120；第 1 人想吃“鸡肉、薯条”，不想吃“辣”；第 2 人想吃“牛肉”，不想吃“鱼” | 偏好是希望满足的要求，不想吃是硬约束。若当前菜单无解，如实展示调整建议 |
| 真实方案 | 点击“生成我的三种方案”，等待官方查询与核价 | 展示忙碌状态。不能在真实查询失败时切换虚构数据冒充成功 |
| 比较 | 查看四种策略，展开逐人分配、满足/未满足清单、优惠依据、查询时间与价格状态 | 重点讲解“照顾最难满足的人”，只把官方核对成功的金额称为已验证价格；不宣称全局最低价 |
| 现场否决 | 对匿名 B 分到的某个实际餐品点击“这份我不接受”，观察重排与重新核价 | 若当前条件无解，展示具体冲突；不能自动放宽这个人的拒绝项 |
| 预算调整 | 改小预算重新生成，展示实际可行方案或预算不足提示 | 说明预算变化对结果的实际影响，不编造省钱数字 |
| 导出 | 选择一张方案，点击“导出所选方案卡”，打开导出的 JSON | 展示匿名分配、门店名、数量、实际价格和时间；不包含 Token、券码或私人偏好原文 |

## 创新片段：预算改变了，谁能少将就

在预算较紧的真实方案上点击“多 10 元能换来什么”，展示相邻候选的真实核价、新增或替换餐品、受益的人和满足项。预算较宽松时可能没有变化，也应如实保留。

这里增加的是预算上限 10 元，实际两张方案的花费差额由官方核价决定，不一定刚好是 10 元。讲解时分别说清原预算、新预算、两端实付及实际差额，核对新方案是否在新预算内。缺少依据或任一端试算失败时，不制作精确差额或成功字幕。

## 失败与演示数据

- 官方超时、门店无货、无解或价格失败要如实显示，不用上一轮结果替代。
- 虚构演示模式可另录短片，文件名和片头明确“演示数据（虚构）”，不能作为真实 MCP 调用证明。
- “堂食/外带”当前是用餐说明，官方已接通业务场景为到店自取，不讲成支持配送或自动下单。
- 既有 [真实验证记录](../outputs/live-verification.json) 可辅助说明，但它不能替代本次录屏的实际返回。

## 放进 GitHub

- 主视频建议命名 `maimen-huican-demo.mp4`；小视频可放 `docs/videos/`。
- 大视频优先作为同一仓库的 Release 附件，README 填实际观看/下载地址。
- 在 `docs/videos/README.md` 记录真实文件、时长、录制日期、门店、数据类型和是否有剪辑加速。
- 录制后检查画面、字幕、隐私与声音；从 GitHub 实际打开视频，再将实际链接补入 README。
- GitHub 上传与比赛正式提交是两步；比赛表单仍需按要求填写作品及演示材料。
