# 麦门会餐：录屏操作与讲解脚本

本文件是录屏计划与复核说明。0.5.0 的主视频已经由脚本真实录制完成（`docs/videos/maimen-huican-demo.mp4`），下面同时保留人工录制的等价步骤，便于复现或重录。

## 录制前

1. 在本项目运行 `npm start`，打开 <http://127.0.0.1:4192/>。不要重复启动已经占用同端口的本项目服务。
2. 确认本机已有有效配置，录制期间不打开 Token 内容或个人收货地址。
3. 程序驱动录制：`PLAYWRIGHT_CORE=<本机 playwright-core> npm run record`。脚本用 Playwright 驱动真实页面并 `recordVideo`，不合成画面、不 mock 接口；人工录制备选是 macOS `Shift + Command + 5` 录制网页区域。
4. 使用公开商圈“上海 / 静安寺”；真实菜单、营业状态和价格以录制当时返回为准，不预设金额。
5. 画面与主题：片头/片尾/导出核对卡必须和网页同一套红黄（`#DA291C` / `#FFC72C` / `#FFF9ED`），不要出现旧版深绿。卡片页要用同源真实导航渲染，不要用 `setContent` 写空白页——那样录像只绘制左上角一小块并露出灰底（0.5.0 已修）。

## 主演示顺序

| 阶段 | 实际操作 | 讲解重点 |
|---|---|---|
| 片头 | 红黄标题卡：几个人一起吃，便宜不等于谁都能接受 | 明确“浏览器自动操作录制”，不假装人工操作 |
| 首页 | 展示新版首页与真实/演示状态 | “几个人想吃的不一样，先把预算和不能接受的食物说清楚。” |
| 连接 | 点击“重新检查连接”，打开再关闭连接设置 | 只查询与价格试算，不创建订单或付款；只显示凭据来源，不显示 Token |
| 门店 | 填城市“上海”、商圈“静安寺”，点击“只查询门店”，选择一家营业门店 | 使用公开商圈，不读取私人地址；清楚展示本次选择的门店 |
| 需求卡 | 人数改为 2、预算先填 120；第 1 人想吃“鸡肉”、不想吃“辣”；第 2 人想吃“牛肉”、不想吃“鱼”；再展示 4 人写法 | 偏好是希望满足的要求，不想吃是硬约束。若当前菜单无解，如实展示调整建议 |
| 真实方案 | 点击“生成四种方案”，等待官方查询与核价 | 展示忙碌状态。不能在真实查询失败时切换虚构数据冒充成功 |
| 比较 | 查看四种策略，展开逐人分配、满足/未满足清单、优惠依据、查询时间与价格状态 | 重点讲解“照顾最难满足的人”，只把官方核对成功的金额称为已验证价格；不宣称全局最低价 |
| 现场否决 | 对匿名 B 分到的某个实际餐品点击“这份我不接受”，观察重排与重新核价 | 若当前条件无解，展示具体冲突；不能自动放宽这个人的拒绝项 |
| 预算调整 | 预算改 55 重新生成，再点“多 10 元能换来什么” | 两端都核价，差额按实际写；无变化就说无变化，不编造受益人或省钱数字 |
| 导出 | 选择一张方案，点击“导出所选方案卡”，打开导出的 JSON | 展示匿名分配、门店名、数量、实际价格和时间；不包含 Token、券码或私人偏好原文 |
| 片尾 | 红黄边界卡 | “只查询与试算，不会替任何人下单”；不承诺最低价，忌口不是过敏原保证 |

## 创新片段：预算改变了，谁能少将就

在预算较紧的真实方案上点击“多 10 元能换来什么”，展示相邻候选的真实核价、新增或替换餐品、受益的人和满足项。预算较宽松时可能没有变化，也应如实保留。

这里增加的是预算上限 10 元，实际两张方案的花费差额由官方核价决定，不一定刚好是 10 元。0.5.0 这一遍的真实结果是：预算 55 → 65，口味方案 ¥46.50 → ¥60.50，**多花 ¥14.00**，新增麦乐鸡 ×1，受益人是匿名 A。

## 失败与演示数据

- 官方超时、门店无货、无解或价格失败要如实显示，不用上一轮结果替代。
- 虚构演示模式不录进主视频；如另录短片，文件名和片头必须明确“演示数据（虚构）”，不能作为真实 MCP 调用证明。
- “堂食/外带”当前是用餐说明，官方已接通业务场景为到店自取，不讲成支持配送或自动下单。
- 既有 [真实验证记录](../outputs/live-verification.json) 可辅助说明，但它不能替代本次录屏的实际返回。

## 录完后的核对

- 用 `ffprobe` 核对时长、分辨率、编码、像素格式；用 `shasum -a 256` 记录哈希。
- 抽帧看开头 / 中间 / 结尾：画面必须铺满 1280×720，没有灰边、黑屏或裁切；字幕不遮挡方案卡按钮与价格。
- 从 GitHub 实际打开视频，再把实际链接补进 README。
- 记录到 [docs/videos/README.md](videos/README.md)：文件、时长、大小、哈希、录制日期、门店、数据类型、是否剪辑加速。
